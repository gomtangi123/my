# Claude Code 단계별 프롬프트

사용법:
1. 이 저장소의 `football/` 폴더에 `CLAUDE.md`가 있다. 모든 작업은 `football/` 안에서 한다.
2. 그 폴더에서 Claude Code를 실행한다.
3. 아래 프롬프트를 **한 단계씩** 복사해서 붙여넣는다. 한 단계가 끝나고 직접 실행해서 확인한 다음 다음 단계로 넘어간다.

---

## 0단계: 데이터 조사
```
CLAUDE.md를 읽고 프로젝트를 파악해줘.
코드 작성 전에 먼저 API-Football에서 대상 대회 13개(유럽 4대 리그, 유럽 중소 리그 6개,
K리그1, J1리그, AFC 챔피언스리그)의 지원 여부, 과거 시즌 수, 시즌 표기 방식,
경기 통계·선수 기록·부상 정보와 xG 제공 여부, 요금제별 호출 한도와 매일 갱신에 필요한
예상 호출 수를 확인해서 README.md에 표로 정리해줘.
내 API 키는 .env에 넣어둘게. 실제 응답을 몇 개 찍어보고 판단해줘.
```

## 1단계: 프로젝트 뼈대 + DB
```
CLAUDE.md의 폴더 구조대로 프로젝트 뼈대를 만들어줘.
config/leagues.yaml, .env.example, DB 스키마(리그, 시즌, 팀, 선수, 경기, 경기통계,
선수기록, 부상, 외부ID 매핑, 팀 별칭)를 만들고 SQLite로 초기화되게 해줘.
```

## 2단계: 데이터 수집기
```
API-Football 수집기를 만들어줘. 원본 JSON 캐시, 호출 횟수 로그, 한도 보호 포함.
1) 과거 시즌 일괄 수집 스크립트 (대상 대회 최근 3~5시즌, 호출 한도 안에서 여러 날에 나눠 이어받기 가능하게)
2) 매일 실행용 갱신 스크립트 (최근 결과, 다가오는 일정, 부상)
먼저 리그 하나로만 테스트해서 DB에 잘 들어가는지 보여줘.
```

## 3단계: 기본 통계 + 피처
```
기본 통계 계산 모듈을 만들어줘: 순위표, 홈/원정 성적, 최근 폼, H2H,
시간대별 득점, 오버/언더·BTTS 비율, 휴식일.
모든 피처는 "경기 시작 시점 이전 데이터만" 쓰도록 하고,
미래 정보가 섞이지 않는지 확인하는 테스트도 작성해줘.
```

## 4단계: Elo + Dixon-Coles 모델
```
Elo 레이팅과 Dixon-Coles 모델(시간 감쇠 포함)을 구현해줘.
walk-forward 방식으로 과거 시즌을 검증하고 Log loss, Brier score, 보정 그래프를 뽑아서
기준선(홈 항상 승, 리그 평균)과 비교한 REPORT.md를 만들어줘.
```

## 5단계: FastAPI
```
프론트에서 쓸 API를 만들어줘:
리그 목록, 순위표, 팀 상세, 선수 상세, 경기 목록(날짜별), 경기 예측 상세, 모델 성능.
시간은 KST로 변환해서 내려주고, API 문서(/docs)로 확인 가능하게 해줘.
```

## 6단계: 프론트엔드
```
Next.js + Tailwind + Recharts로 CLAUDE.md의 화면 6개를 만들어줘. 모바일 우선, 한국어.
로고·선수 사진 대신 팀 컬러 원형 배지를 쓰고, 경기 상세에는 스코어 확률 히트맵과
참고용 고지문을 넣어줘. 먼저 홈 화면과 경기 상세부터 만들어서 보여줘.
```

## 7단계: 자동화
```
매일 새벽(KST) 데이터 갱신 → 통계 재계산 → 예측 갱신이 자동으로 돌도록 스케줄러를 붙여줘.
실패 시 로그를 남기고, 다음 날 자동 재시도되게 해줘.
```

## 8단계: 고급 모델 (데이터가 쌓인 뒤)
```
xG를 제공하는 리그에 대해 xG 기반 Dixon-Coles를 추가하고,
Elo·모델 확률·폼·휴식일을 피처로 쓰는 LightGBM 모델을 만들어줘.
기존 모델과 같은 방식으로 검증해서 REPORT.md 비교표를 업데이트하고,
더 나은 모델만 사이트에 반영해줘.
```

## 9단계: 배포
```
PostgreSQL로 전환하고 배포 준비를 해줘.
백엔드와 프론트를 어디에 올리면 좋을지 비용 기준으로 2~3가지 추천하고,
선택한 곳에 배포하는 방법을 단계별로 정리해줘.
```
