# 축구 분석·예측 웹사이트 (유럽 + 아시아)

## 프로젝트 개요
유럽 주요 리그(4대 리그 포함)·유럽 중소 리그와 아시아(K리그·J리그·AFC 챔피언스리그)를 대상으로 하는 축구 분석 + 경기 예측 웹사이트.
- 사용자는 팀·선수 통계와 차트를 보고, 다가오는 경기의 승/무/패·스코어 확률을 확인한다.
- 사이트 언어: **한국어** (유럽·일본 팀/선수는 영문 원어 표기 + 가능하면 한글 병기, K리그는 한글 표기 우선)
- 주 사용 환경: **모바일** (모바일 우선 반응형)

### 대회별 특수 사항 (설계 시 반드시 반영)
- **시즌 표기가 리그마다 다르다.** 유럽은 8월~5월(예: 2025-26), K리그는 단일 연도(예: 2025).
  J리그는 2026-27 시즌부터 8월~5월 추계·춘계제로 전환되었고, 그 사이 2026년 상반기에 특별 대회가 있었다.
  → 시즌은 "시작일·종료일"로 관리하고, "2025-26" 같은 문자열 형식을 가정하지 않는다. 실제 API 응답으로 확인할 것.
- **K리그1 스플릿 라운드**: 정규 라운드 후 상·하위 스플릿(파이널 A/B)으로 나뉜다. 순위표·잔여 일정 계산이 이를 처리해야 한다.
- **AFC 챔피언스리그는 컵 대회**다.
  - 서로 다른 리그 팀끼리 맞붙으므로, 리그별로 따로 학습한 Dixon-Coles 공격/수비력은 바로 비교할 수 없다.
    → 리그 간 전력 보정(리그 강도 계수, 또는 리그 통합 Elo)을 둔다.
  - 리그 스테이지 + 토너먼트 구조. 토너먼트 경기는 연장·승부차기가 있으므로 예측은 **90분 결과** 기준으로 하고, 진출 확률은 별도로 표시한다.
  - 결승 라운드가 중립 경기장(집중 개최)에서 열리는 경우가 있다 → 경기마다 `neutral_venue` 플래그를 두고, 중립 경기면 홈 어드밴티지를 끈다.
- 4대 리그는 데이터가 풍부하지만, 아시아 대회는 경기 통계·xG·선수 기록 제공 범위가 좁을 수 있다. 제공되지 않는 지표는 화면에서 숨긴다.

## 기술 스택
- **백엔드 / 데이터 / 모델**: Python 3.11+, FastAPI, SQLAlchemy, pandas, numpy, scipy, scikit-learn, LightGBM
- **DB**: 개발은 SQLite, 배포는 PostgreSQL (SQLAlchemy로 둘 다 지원)
- **프론트엔드**: Next.js (App Router) + TypeScript + Tailwind CSS, 차트는 Recharts
- **스케줄러**: 데이터 수집·모델 재계산은 cron 또는 APScheduler로 매일 자동 실행
- 패키지 관리: 백엔드 `uv` 또는 `pip` + `requirements.txt`, 프론트 `npm`

## 폴더 구조 (목표)
```
/backend
  /app            FastAPI (API 라우트)
  /collectors     데이터 수집 (API 클라이언트, 캐싱)
  /models         예측 모델 (elo, dixon_coles, xg_model, ml_model)
  /features       피처 생성 (폼, 휴식일, H2H 등)
  /db             스키마, 마이그레이션
  /jobs           일일 배치 작업
  /tests
/frontend         Next.js
/config           leagues.yaml, settings
/data             원본 응답 캐시(raw json) — git 제외
```

## 데이터 소스
- 기본: **API-Football (api-sports.io)** — 유럽·아시아 리그 커버리지가 넓음
- 작업 시작 전 반드시 확인하고 결과를 README에 기록할 것:
  1. 대상 대회 각각이 지원되는지, 몇 시즌치 과거 데이터가 있는지
  2. 대회별로 경기 통계(슈팅, 점유율 등)·선수 기록·부상 정보와 **xG 제공 여부**
  3. 요금제별 하루 호출 한도, 그리고 대상 대회 전체를 매일 갱신하는 데 필요한 예상 호출 수
- API 키는 `.env`의 `API_FOOTBALL_KEY`로만 읽는다. 키를 코드나 커밋에 절대 넣지 않는다. `.env.example` 제공.
- 데이터 소스는 어댑터 패턴으로 감싸서 나중에 다른 API로 교체 가능하게 한다.

### 호출 한도 관리 (중요)
- **요금제: Free (하루 100회)** 로 운영한다. 요금제·한도 값은 `config/settings.yaml`에서만 관리한다.
- 모든 API 응답은 원본 JSON을 `/data/raw`에 캐시하고, 이미 받은 데이터는 다시 호출하지 않는다.
- 종료된 경기는 한 번 받으면 끝. 매일 갱신은 "최근 경기 결과 + 다가오는 일정 + 부상/결장"만.
- 대회 수가 많으므로 대회별 우선순위를 `leagues.yaml`에 두고, 한도가 부족하면 우선순위 낮은 대회부터 다음 날로 미룬다.
- 호출 횟수를 로그로 남기고 한도 근처에서 멈춘다.

## 데이터 정합성
- 팀·선수는 내부 ID로 관리하고, 외부 API ID와 매핑 테이블을 둔다.
- 팀 이름 표기 통일 (별칭 테이블). 한 팀이 리그와 AFC 챔피언스리그에 모두 나오므로 같은 내부 ID로 묶인다.
- 경기 시간은 UTC로 저장, 화면에서는 한국 시간(KST)으로 표시.

## 분석 기능
### 기본 통계
- 순위표(K리그 스플릿, ACL 조/리그 스테이지 포함), 홈/원정 성적, 최근 5·10경기 폼
- 상대 전적(H2H)
- 시간대별 득점·실점(15분 단위), 선제골 시 승률
- 오버/언더 2.5, 양팀득점(BTTS) 비율
- 코너킥, 카드, 슈팅 수

### 고급 지표 (데이터가 있는 대회만, 없으면 화면에서 숨김)
- xG / xGA, xG 대비 실제 득점 차이
- 점유율, 패스 성공률

### 선수
- 득점·도움, 90분당 환산 기록, 출전 시간
- 부상·결장 목록
- 같은 포지션 선수 비교 레이더 차트

### 상황 변수
- 휴식일 수, 최근 N일간 경기 수 (리그 + ACL 병행 일정 포함)
- ACL 원정 이동 거리·시차 (아시아 대회는 이동 부담이 큼)
- 감독 교체 이후 성적

## 예측 모델 (단계적으로 구현, 각각 독립 모듈)
1. **Elo 레이팅** — 홈 어드밴티지 포함, 시즌 간 평균 회귀. 리그 통합 Elo로 ACL 같은 리그 간 경기에도 쓸 수 있게 한다.
2. **Dixon-Coles 포아송 모델** — 메인 모델
   - 팀별 공격력/수비력 + 홈 어드밴티지(리그별) + 저득점 보정(rho)
   - 최근 경기에 가중치를 주는 시간 감쇠(time decay) 적용
   - 리그 간 경기(ACL)는 리그 강도 보정 항을 추가
   - 출력: 스코어 확률 행렬(0~10골) → 승/무/패, 오버/언더, BTTS, 가장 가능성 높은 스코어
3. **xG 기반 모델** — xG가 있는 대회에서만, Dixon-Coles 입력을 골 대신 xG로
4. **LightGBM** — Elo, 모델 확률, 폼, 휴식일, 홈/원정 등을 피처로 사용. 데이터가 충분히 쌓인 뒤

### 평가 규칙 (반드시 지킬 것)
- **미래 정보 누출 금지**: 피처는 반드시 경기 시작 시점 이전 데이터로만 계산.
- 검증은 시간 순서 분할(walk-forward). 랜덤 분할 금지.
- 지표: **Log loss, Brier score, 보정(calibration) 그래프**. 단순 적중률만으로 판단하지 않는다.
- 기준선: "홈팀 항상 승리", "리그 평균 확률"과 비교. 배당 데이터가 있으면 배당 내재 확률과도 비교.
- 성능은 **대회별로 따로** 보고한다 (4대 리그·중소 리그·아시아는 성격이 달라 합치면 가려진다).
- 모델별 성능 비교표를 `/backend/models/REPORT.md`에 자동 생성.

## 화면 구성
1. **홈**: 오늘·이번 주 경기 목록 + 각 경기 승/무/패 확률 막대 (지역 탭: 전체 / 유럽 / 아시아)
2. **리그 페이지**: 순위표, 득점 순위, 리그 평균 지표 (ACL은 조/리그 스테이지 표 + 대진표)
3. **팀 페이지**: 폼 그래프, 홈/원정 분리 통계, 시간대별 득점 차트, 주요 선수, 부상자
4. **경기 상세 (예측)**: 두 팀 나란히 비교, 스코어 확률 히트맵, 오버/언더·BTTS 확률, H2H, 모델 설명
5. **선수 페이지**: 기록, 레이더 차트
6. **모델 성능 페이지**: 지난 경기 예측 vs 실제 결과, 보정 그래프 (투명성용)

## 법적·운영 규칙
- 리그·구단 로고, 엠블럼, 선수 사진은 **사용하지 않는다** (저작권·초상권). 팀 컬러 원형 배지 + 약칭으로 대체.
- 데이터 출처 표기 (푸터).
- 예측은 "통계 모델에 따른 참고 정보"라는 고지문을 경기 상세 화면에 표시.
- **베팅 사이트 링크, 배너, 추천 코드, 픽 판매 기능 넣지 않는다.** (국내 사설 베팅 홍보·연계는 불법)
  K리그는 국내 체육진흥투표권 대상 경기이므로 특히 베팅 관련 문구·연계를 넣지 않는다.

## 작업 방식
- 한 단계씩 진행하고, 각 단계 끝에 실행 방법과 테스트 결과를 보고한다.
- 각 모듈은 테스트 작성 (특히 모델 계산, 피처 생성의 미래 정보 누출 여부).
- 설명과 커밋 메시지는 한국어로.
- 모르는 API 사양은 추측하지 말고 문서 확인 또는 실제 응답을 찍어보고 진행.
